# 2026-10-16 大文件上传修复与出包记录

## 历史数据丢失排查

复核了 2026-05-26 的项目会话。当时发现的高风险路径是：磁盘状态文件为空或缺少卡片时，手机端定时刷新会直接覆盖内存。后续加入了以下保护，当前代码继续保留：

- `saveState` 默认拒绝空状态覆盖已有非空状态，并写入 `blocked-empty-overwrite` 备份。
- `_wouldDropPhoneCards` 拒绝磁盘刷新删除手机内存中已有卡片。
- 导入时拒绝空备份。

历史最终处理：升级版本、生成 release APK，并用同签名 `adb install -r` 覆盖安装，没有卸载。历史构建缓存问题另见 `2026-05-10-apk-build-debug-log.md`；签名兼容问题另见 `2026-07-21-localshare-stability-and-lan-bookmark.md`。

## 本次修复

原网页通过 FileReader 将整文件变成 Base64，再序列化 JSON；大文件会显著增加内存需求。空读取结果会被保存为零字节附件，网页也没有检查 HTTP 失败状态。

现在网页使用 FormData 直接发送文件，服务端逐段写入临时文件并检查实际大小，完整接收后才创建卡片。失败保留网页输入和已选文件。临时对话上传也走相同通道；临时对话存为卡片时复制本地附件，不再整文件读入内存。

验证：600 MiB 实际 HTTP 流传输、落盘大小与首尾字节检查；大小不符、缺失附件及临时文件清理；网页成功和失败状态处理。该测试不替代手机上的端到端 ZIP 上传验证。

## 本次出包约束

- 初次修复版本：`1.0.25+26`；上传进度版本：`1.0.26+27`。
- 使用 `make release-apk`，保留 `localshare.local.mk` 注入的接口配置。
- 保留包名、既有签名配置、存储位置及上述数据保护。
- 用户随后明确要求直接覆盖安装，禁止卸载。`1.0.25+26` 已通过 `adb install -r` 安装成功。
- 安装仅用 `adb install -r`；如果安装失败，排查原错误，不以卸载或清数据解决。用户明确不要求备份旧 APK，不再增加备份步骤。

## 上传进度

网页上传改用 XMLHttpRequest 上传事件，展示百分比、传输字节数、平均速度和耗时。文件传完后继续显示保存阶段，收到服务端成功响应才显示完成。未知长度时使用不定进度；失败保留输入及文件。Web 临时附件在同一文件系统中通过重命名移入最终目录，避免传完后再次复制大文件。
