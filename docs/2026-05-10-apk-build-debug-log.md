# 2026-05-10 APK 反复打包但界面不生效排查日志

## 背景

这次在 `localshare` 上连续做了多轮 UI 和交互调整，包括：

- 手机端首页布局调整
- 顶栏和设置入口调整
- 卡片滑动操作
- 导入导出
- web 端链接打开和粘贴图片
- 访问地址卡片的服务状态交互

但中途出现了一个很误导的问题：

> 明明已经重新编译、重新安装，手机上看到的界面还是旧的，像是改动根本没有生效。

这个问题导致后续很多判断都被污染了，需要单独留档。

## 现象

主要现象有几个：

1. 版本号已经变化，但界面没变化。
2. release APK 明明重新构建成功，手机上看起来仍像旧包。
3. 某些功能在源码里已经删除或改位，手机界面却还保留旧按钮。
4. 同一个问题会在“重新编译后依然无变化”和“突然又生效”之间反复切换。

最典型的一次是：

- 源码里顶栏已经只剩设置按钮
- 手机上仍然看到“设置 + 到顶 + 到底”

这说明问题不是单纯的“功能写错”，而是构建链路或安装链路存在脏状态。

## 初步误判

排查早期出现过几种误判：

1. 误以为只改到了 web 端，没有改到手机 app 端。
2. 误以为手机安装的不是当前目录构建出来的 APK。
3. 误以为版本号变化就足够证明 APK 一定是新的。
4. 误以为 release 构建成功就意味着最终安装和运行结果一定对应当前源码。

这些判断后来都证明不够硬。

## 关键证据

后面靠几类证据逐步收口：

### 1. 直接读源码确认 app 端确实改了

项目只有一个 Flutter 主入口：

- `lib/main.dart`

而且关键 UI 改动明确存在于 app 端 Flutter 代码里，不是只在嵌入的 web HTML 中。

### 2. 截图和源码对不上

用户提供的手机截图里仍然存在旧 UI：

- 顶部旧按钮还在
- 搜索框位置还是旧的
- 新加的设置项和展示项没出现

这证明：

> 手机上运行出来的界面，和当前源码不是同一份结果。

### 3. release 构建过程中出现 `Invalid depfile`

某次构建日志里大量出现：

```text
Invalid depfile: .../.dart_tool/flutter_build/.../kernel_snapshot_program.d
```

这基本说明 Flutter 增量构建状态已经脏了。

### 4. `flutter clean` 本身崩溃

尝试标准清理时，Flutter/Dart 工具链直接崩掉：

```text
cpuinfo_macos.cc: 42: error: unreachable code
```

也就是说，不能指望用一次普通 `flutter clean` 就把环境拉回干净状态。

## 真正转折点

真正把问题往前推进的是：

### 手工清理项目内缓存，而不是只依赖 `flutter clean`

做过的关键动作：

- 删除项目内 `build/`
- 删除 `.dart_tool/flutter_build`

之后再重新执行 release 构建，`Invalid depfile` 不再出现，说明这一步是有效的。

## 结论

这次“反复打包但界面不生效”的核心不是单一原因，而是几件事叠在一起：

1. Flutter 增量构建缓存脏了。
2. 某些轮次安装到手机上的不是刚刚那次构建完成后的最新 APK。
3. 版本号变化不足以证明界面资源和 Dart 产物一定同步更新。
4. 一旦构建链路处于脏状态，就会让“源码已改但 UI 不变”这种现象反复出现。

## 后续稳定做法

后面如果再遇到类似情况，建议直接按这个顺序处理：

1. 先在源码里加一个一眼能看出的验证改动。
   例如标题文案、明显按钮文案、显眼颜色块。

2. 不要只看版本号。
   版本号只能证明 manifest 变了，不能证明 UI 一定对应当前源码。

3. 手工清理项目内构建产物。
   优先清：
   - `build/`
   - `.dart_tool/flutter_build`

4. 重新构建 release APK。

5. 构建完成后再安装。
   不要在 release 还没结束时抢先装旧 APK。

6. 安装完成后立刻核对那个“验证改动”是否出现。

## 这次额外踩到的两个环境问题

### 1. ADB 权限问题

在当前代理环境里，多次出现：

```text
ADB server didn't ACK
could not install *smartsocket* listener: Operation not permitted
```

这不是 APK 本身的问题，而是当前环境无法直接接管本机 adb daemon，需要提权后才能安装。

### 2. 磁盘空间不足

后期又出现过一次构建失败：

```text
No space left on device
```

这会导致：

- APK 复制失败
- Gradle 锁释放异常
- 构建结果不完整

所以当出现“明明刚构建过但 APK 行为异常”时，也要检查磁盘空间。

## 当前结论

这次问题不是单纯“代码没写进去”，也不是单纯“用户装错包”。

更准确地说，是：

> Flutter release 增量产物、安装时机、工具链状态和本机环境问题叠加，造成了“反复打包但界面不生效”的假象。

把这件事写下来，是为了以后再碰到“源码和手机界面对不上”的情况时，不要再先怀疑业务代码本身，而是优先检查构建缓存、构建顺序、安装时机和环境状态。
